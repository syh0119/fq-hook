# 番茄导出（fq-hook）

番茄小说（`com.dragon.read`）的 **LSPosed 模块**：把番茄**已经解密到内存里**的章节正文
导出成 **TXT / EPUB**，支持**多本多选一次导出**，EPUB 含**插图与章节目录**，
导出过程有**进度条**，导出后自动与**原始排版 XHTML 逐章校对**。

> 本模块**不实现任何解密算法**，也不碰密钥推导。它运行在番茄进程内，直接调用宿主自己的
> native 解密例程，然后把明文结果落盘。

> ### ⚠️ 先看这一条
> 章节台账是**纯内存**的，只存在于**本次番茄进程存活期间**。番茄被强停 / 重启 / 被系统回收后，
> 捕获到的章节全部消失，书籍列表归零。想导哪本就**先在番茄里下载或翻过那本**，
> 并**在同一次进程存活期内导完**。详见 [⚠️ 注意事项](#注意事项必读)。

---

## 功能

| 功能 | 说明 |
|---|---|
| 手动导出 | 章节先进内存缓冲，点设置面板里的导出按钮才写出整本。默认不自动落盘 |
| **多书多选** | v1.10.0 起面板可勾选多本（`☑`/`☐` 翻转勾选，另有 `全选`/`全不选`），点一次按钮**串行导出全部勾选的书** |
| 两种格式 | `TXT`（纯文本，插图处留占位）／ `EPUB`（插图嵌正文 + 章节目录），默认 TXT |
| 插图 | 从宿主私有目录读出明文 JPEG/PNG，EPUB 内嵌、TXT 模式另存为 `<书名>_i0001.jpg` |
| 目录 | EPUB 2.0.1 + `toc.ncx`，一章一条 `navPoint`，可直接导入阅读器跳章 |
| 进度条 | 解析章节 → 打包 EPUB → 校对，分阶段实时进度；多本时按本数分段，0→100% 一路走完 |
| 校对 | 导出后把结果与**原始排版 XHTML** 逐章比对（字数、块、插图），全文写进 `_运行日志.txt` |
| EPUB 自检 | 打包后校验文件本身是否成立（mimetype 首条目且 STORED、必备条目、章/图计数、manifest 引用全部命中） |
| 输出扁平 | v1.9.0 起所有文件直落 `Download/番茄导出/`，不建书名子目录、不写独立校对报告 |
| 设置界面 | 挂在番茄「我的」页底部固定栏，点开即模块设置面板；主面板只留列表与导出，其余收进「更多设置」 |

## 原理

一句话：**模块不实现任何解密算法**，而是运行在番茄进程内，借宿主的密钥和native 例程
把已经解密出来的明文「顺手截下来」，再自己拼成 TXT / EPUB。

### ① 不碰密钥，只借宿主现成的

```
com.dragon.read.crypt.CryptManager
    byte[] decrypt(String 密文, String 书级key, int keyVer)   // public static native
```

实现在宿主的 `libdragon_crypt.so` 里，返回值恒为 gzip，解压即排版XHTML。
书级密钥由宿主自己保管并喂给这个函数 —— 模块只是**在调用发生后把返回值捞出来**，
既不推导 keyVersion，也不实现 AES。所以宿主一改密钥体系，失效的只会是 hook 点，不是模块逻辑。

### ② 四个 hook 点协同

| 落点 | 拿到什么 |
|---|---|
| `ChapterInfo.a(ItemContent, boolean)` | 下载/读取瞬间拿到 密文 + 书名 + 章节名 + chapterId + keyVersion |
| `DecryptKey.<init>` | 旁听书级密钥（v2 key + mVer），宿主给什么用什么 |
| `reader.utils.n.a(ChapterInfo, DecryptKey)` | 阅读器解密入口，返回**已解压明文** —— 覆盖「已下载从 DB 读」这条路径 |
| `CryptManager.decrypt` | 被动兜底截获 |

前两个负责**拿到定位信息**（哪本书哪一章），后两个负责**拿到正文**。
`reader.utils.n.a` 是覆盖面最广的一个：走它的是阅读器正常渲染流程，
所以「已下载但没在读」的章节也能被抓到，而不只是当前这一章。

### ③ 明文进内存台账，按 bookId 分桶

```
bufPut(密文, 书名, 章节名, chapterId, keyVersion)
   └─ 解压去标签 ─→ BUF[bookId][chapterId] = 正文
                    BOOK_NAME[bookId] = 书名     ← 列表显示用
                    BOOK_SEEN[bookId] = 时间戳   ← 按「最近读过」排序
```

台账在**内存**里，按 `bookId` 分桶 —— 这样多本书互不干扰，同名不同书也不覆盖。
点导出时才遍历台账拼文件（默认不自动落盘，见下文「为什么必须手动点导出」）。

### ④ 导出：MediaStore 写入 + 两道自检

v1.9.0 起文件全部**平铺**写在 `Download/番茄导出/`，文件名自带书名。
写入走 `MediaStore`（targetSdk=35 作用域存储下，直接 `File` 写 `/sdcard` 会被拒）。
导出完做两道检查，都写进 `_运行日志.txt`：

1. **EPUB 结构自检** —— mimetype 是不是首条目且 STORED、必备条目齐不齐、
   章/图计数、manifest/spine 引用有没有悬空
2. **与原始 XHTML 逐章校对** —— 源侧去标签数字符、导出侧数字符，两边独立算，
   差多少字就是丢了多少

> UI 注入挂在 `androidx.fragment.app.Fragment` 基类上，用**文本锚点**（如「我的订单」）
> 识别页面，不依赖类名与混淆 id，因此对宿主改版天然免疫。

## 安装

1. 从 [Releases](../../releases) 下 `fq-hook-lsp-v<版本>.apk`（或直接用 `dist/` 里的）
2. LSPosed 里启用模块，作用域勾选 **番茄小说**（`com.dragon.read`）
3. 强行停止番茄后重新打开（**必须重启进程**，否则 hook 不生效）
4. 进入番茄「我的」页，页面最底部会出现 **「🍅 番茄导出设置」** 入口

> 验证是否装上：面板标题写的就是模块版本号；LSPosed 管理器里显示的也应是同一版本。
> 若面板还是旧版本，多半是番茄没被强停过。

## 使用方法

> **顺序很重要：先在番茄里下载小说，再回到导出设置里导出。**
> 模块只能拿到宿主**已经解密过**的章节 —— 没下载过的章节它看不见。

```mermaid
flowchart LR
    A["① 番茄打开小说<br/>点顶部「下载」"] --> B["② 我的 →<br/>🍅 番茄导出设置"]
    B --> C["③ 勾选要导的书<br/>可多选"]
    C --> D["④ 点「导出 N 本」"]
    D --> E["Download/番茄导出/"]
```

### ① 在番茄里下载小说

打开要导出的小说 → 阅读页顶部点 **「下载」**（点完按钮会变成「查看下载」）。

也可以直接往下读几章 —— 读过的章节宿主同样会解密，模块一样能抓到。

**这一步不能省。** 模块是跟着宿主的解密动作抓数据的，宿主没解密过的章节，模块看不到。

### ② 回到「我的」页，打开导出设置

番茄底部 tab → **我的** → 页面最底部 **「🍅 番茄导出设置」**

面板上会直接写着这两步：

```
① 在番茄里打开任意一本书
② 点阅读页顶部的「下载」（或直接往下翻几章）
③ 回到这里，书名就会出现在列表里
```

### ③ 勾选书（可多选）→ 点统一导出按钮

v1.7.0 起面板主体就是**书籍列表** —— 捕获过几本就列几本，按「最近读过」排序。
v1.8.0 起交互改成**两步**：点行只负责**勾选**，导出统一走下方红色按钮
（避免手滑点一下就直接开跑）。
**v1.10.0 起支持多选** —— 可以一次勾好几本，点一次导出按钮全部出图。

```
番茄导出 v1.10.0
已捕获 3 本 · 共 128 章　（已选 3 本 · 128 章）
┌────────────────────────────────────────┐
│ [全选] [全不选] 可多选                │
│ 《重生：都市修仙》      ☑ 已选 │  ← 最近在读 · 96 章 · EPUB
│ 《从零开始的剑修生活》  ☑ 已选 │  ← 24 章 · EPUB
│ 《末世第一物流中心》    ☐ 选择 │  ←  8 章 · TXT
└────────────────────────────────────────┘
      导出 3 本 · 共 128 章 [EPUB]     ← 点了它才开始导出
  将依次导出 3 本  点上面的红色按钮开始（逐本进行，完一本再下一本）
        [ 更多设置 ]   [ 完成 ]
```

- 点行**翻转**该本的勾选态（再点一次取消），已勾选的行有主色描边 + `☑ 已选`
- 选中 1 本时按钮显示**书名 + 章数**；选中多本时显示**本数 + 总章数**
- 默认自动勾选最近读过的那本；番茄重启导致缓冲清空时会自动回退
- 多本**逐本串行**导出：进度条按本数分段，0→100% 一路走完，完一本再下一本；
  某本失败不中断后面的，最后统一报「成功 N 本」+ 失败的书名
- 导出进度条走完 → 面板显示每本的结果与校对结论

> **章节缓存在内存里，番茄进程被清空即失效。** 想导哪本就先在番茄里翻过那本，
> 并且**在同一次番茄进程存活期内导完**。这条限制的完整说明见下方 [注意事项（必读）](#注意事项必读)。

### ④ 取文件

输出目录：`/sdcard/Download/番茄导出/` —— **所有文件直接落在这一层，不建子文件夹**。

```
<书名>.txt               纯文本
<书名>.html              图文混排（TXT 模式附带）
<书名>.epub              插图 + 目录（EPUB 模式）
<书名>_i0001.jpg …       插图本体（文件名带书名，不会跟别的书撞）
<书名>_章节索引.tsv      逐章索引
_运行日志.txt            模块运行日志（校对全文在里面）
_开关.txt                开关配置（与设置面板双向同步）
```

> v1.9.0 起不再为每本书建子目录、不再单独写 `_校对报告.txt` ——
> 打开 Download 就能一眼看到所有小说，不用先点进文件夹。

### 常见情况

| 现象 | 原因 / 处理 |
|---|---|
| 点导出提示「暂无可导出的章节」 | 还没捕获到 —— 回第 ① 步，先在番茄里下载或读几章 |
| 只导出了几章，不是整本 | 模块只拿到你下载/读过的那几章。要整本，先在番茄里**下载全本**再导出 |
| 番茄重启后「已缓存 N 章」清零 | 缓冲在内存里，进程重启即清空。重新下载/阅读即可 |
| 导出后没看到插图 | 那几章本来就没图。日志里的 `插图 N 张` 是判定依据 |

**为什么必须手动点导出**：实测番茄把「读过的章节」也缓存到
`files/<uid>/prefix_public_<bookId>/<chapterId.hashCode()>`，与「用户点下载」在
解密层面完全同构（同路径、同 boolean 参数、同调用栈、无系统通知），自动分辨不出来。
所以由用户按一下来表态。

## 注意事项（必读）

### ① 章节只存在于「本次会话」的内存缓存里

**这是本模块最容易被误解的一点，务必先看。**

模块的章节台账（`BUF`）是**纯内存**的，进程一死就归零：

```
番茄进程启动  →  台账空
   ↓  你在番茄里下载/阅读某本书
捕获到章节     →  台账累积（这才是你能导的东西）
   ↓
番茄被强停 / 划掉 / 重启 / 系统回收内存 / 杀后台
台账归零       →  面板里「已捕获 N 本 · M 章」全部清空，书也消失了
```

**所以：**

- 想导哪本书，**必须先在番茄里把它过一遍**（点「下载」或往下翻几章），再回到面板导出
- 导出**要在同一次番茄进程存活期内完成**。攒一天导一次是不行的 —— 中间番茄被系统
  杀一次，前面积累的全没了
- 面板里的书列表**不会持久化**，下次打开番茄是空的，属正常现象，不是 bug
- 番茄自身的下载缓存还在（那部分模块动不了，也不需要动）；模块只是**没有把密文缓存
  重新解出来的能力** —— 解密必须等宿主真的去读那一章时才发生

> 换句话说：**模块不是「导出番茄已下载的章节」，而是「导出番茄本次运行期间解过的章节」。**

### ② 只能拿到宿主解密过的章节

模块没有独立解密能力，只能截获宿主解密的那一瞬间。所以：

- **未下载、未读过的章节，模块永远看不到**
- 想导出整本 → 必须先在番茄里**下载全本**
- 单次捕获上限 **5000 章/本**

### ③ 只导出了几章 = 模块只捕获了几章

面板里每本书后面标的章数就是**实际能导出的章数**，不是番茄目录里的总章节数。
模块读不到番茄的目录缓存（下载目录文件名是 `chapterId.hashCode()`，hash 不可逆，
无法只靠扫目录还原章节顺序与总数），所以校对报告里的「分母」也只是本次捕获数。

### ④ 宿主版本更新后可能失效

hook 点是番茄的内部类名与方法签名，**不是公开 API**。番茄一旦改版（混淆 id 变、
类名改、方法签名变），模块可能抓不到数据或直接崩溃。当前已测：
7.2.7.32（API 36）、7.3.9.32（API 37）。

### ⑤ 需要 root + LSPosed，且必须强停番茄

KernelSU / Magisk / APatch 任一 + LSPosed v1.8+。
装完不重启番茄进程 = hook 不生效，面板入口都不出现。

### ⑥ 导出物请自用

导出内容版权归原作者与平台所有。仅供个人学习与备份已购内容，请勿传播或商用。
详见文末[免责声明](#免责声明)。

## 设置面板

番茄「我的」页底部点进面板。主面板只管**看有哪些书、勾选要导的书、点导出**，
下面这些都收在「更多设置」里（开关写入 `_开关.txt`，与面板双向同步）：

| 开关 | 默认 | 作用 |
|---|---|---|
| 自动导出 | 关 | 开 = 边读边导（旧行为）；关 = 只在你点导出按钮时落盘 |
| 导出插图 | 开 | 把章节内嵌插图另存为 `<书名>_i000N.jpg`（EPUB 内嵌也受此开关控制） |
| 保存 XHTML 原文 | 关 | 额外保留番茄原始排版文件（`.xhtml`） |
| 强制重新导出 | 关 | 忽略「已导出」记录，同一章再导一次（用于补文件） |

「更多设置」里还有：格式选择（TXT / EPUB）、运行日志、校对结果。

## 校对结果

v1.9.0 起**不再单独写 `_校对报告.txt`** —— 全文打进 `_运行日志.txt`，
设置面板点「校对结果」能从日志里把最近一次报告捞出来显示：

```
《书名》导出校对报告
时间 2026-10-10 01:35:17
格式 EPUB
──────────────────────────────
导出结果  ✔ 导出 EPUB《书名》 7/7 章 · 插图 0 张 · 33 KB
章节      7 / 7  （分母 = 模块本次捕获到的章节数，不是番茄目录总数）
正文      18,989 字  |  原始 XHTML 18,989 字  |  偏差 +0
插图      0 / 0 张
──────────────────────────────
结论      ✔ 与原始排版一致，未发现丢字/丢块
          ⚠ 未被捕获的章节在此报告中不可见（模块拿不到番茄目录总数）。
```

口径：源侧把原始 XHTML 去标签后数**非空白字符**，导出侧数最终落盘内容，两边**独立计算**，
所以能真实暴露解析中断、块丢失、图注被吞。

**结论分四态，任何异常都不给「✔」**：

| 结论 | 触发条件 |
|---|---|
| ✔ 一致 | 无空章、无降级、无字数/图偏差，且全部章节都有正文 |
| ✘ N 章存在差异 | 导出字数或插图数与源侧不符 |
| ✘ N 章走了兜底解析 | 该章 `<blk>` / image div 一个都没认出来，走了「整份去标签」兜底 —— **结构全丢，但字数会与源侧虚假相等**，所以必须单列，禁止判一致 |
| ✘ N 章解析不出正文 | 捕获到了却有密文解析不出，导出里根本没这一章（报告末尾列出章节号+章节名） |

最后一种情况要注意：**未被捕获**的章节在报告里是完全不可见的（模块不读番茄目录缓存，
拿不到真实章节总数）。报告里的「分母」只是本次捕获数，别把它当成全书章节数。

## 构建

无 Gradle，纯手工链路（`aapt2` + `javac` + `d8` + `zipalign` + `apksigner`）。
`build.sh` 里的 `TOOLS` / `SDK` / `KS` 三个变量指向本机 Android SDK build-tools、
`android.jar` 与签名 keystore，按自己的路径改掉即可。`ROOT` 由脚本自定位（脚本所在目录），不用配。

```bash
bash build.sh
# 产物: out/fq-hook.apk
# 发行: dist/fq-hook-lsp-v<版本>.apk + 同名 .sha256（脚本自动生成）
```

**版本号单一来源**：只维护 `MainHook.java` 里的 `VERSION` 常量。
`build.sh` 从源码里读它，`versionCode` 由版本号自动推导（`1.2.3` → `10203`），
发行 APK 文件名也按它命名 —— 三处手改的历史到此结束。

`lib/api-82.jar` 是编译期依赖（Xposed API），不打进 APK。

### 离线自测

`tools/selftest/FqSelfTest.java` 直接反射调用宿主编译产物里的纯静态逻辑，
不需要设备即可回归：`esc()` 的 XML 非法字符过滤、脏字符计数、EPUB 结构自检

## 已知边界

> 用户视角的注意事项见上方 [注意事项（必读）](#注意事项必读) 一节，这里是实现层面的取舍。

- **整本导出的前提**是模块捕获过该书的章节：想导整本，得先让番茄把章节过一遍
  （读一遍或点一次下载）。原因：下载目录里的文件名是 `chapterId.hashCode()`，
  hash 不可逆，无法只靠扫目录还原整本。
- 缓冲在内存里，番茄进程重启即清空 —— **这是当前最大的功能限制**（见注意事项①）。
  已评估过的替代方案「扫盘解密已下载章节」卡在每本书 keyVersion 密钥不同，未实现。
- 单次捕获上限 5000 章/本。
- 书籍列表按 `bookId` 分桶，**同名不同书互不覆盖**，但也不做跨进程持久化。
- **EPUB 已实测**：真机导出 **273 章 / 23,579 段 / 1.15 MB**；v1.6.3 起这些检查
  （`mimetype` 规范与是否 STORED、`content.opf` 的 manifest/spine 引用、
  `toc.ncx` 目录条数与章节数一致、各条目可完整读出）已**内建为导出后自检**，
  结论直接写进 `_运行日志.txt`，不用再事后人工跑。
- 插图路径由离线测试覆盖（构造多章多图，校验图片文件与正文引用），
  真机侧需翻到含插图的章节才能看到 `插图 N 张`。
- **XML 脏字符**：正文里的控制字符（0x00-0x1F 中除 Tab/LF/CR 者）会被替换成
  `U+FFFD` 并计入报告「脏字符」行 —— 这是防止整本 EPUB 被阅读器判「损坏」；
  如果不想被替换，请在导出的 TXT 里核对原始文本。
